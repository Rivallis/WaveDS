# Contributing to WaveDS

We welcome contributions to the WaveDS dataset and related tools! This document outlines how you can contribute to this open research initiative.

## Types of Contributions

### 1. Dataset Contributions

**Additional measurements**:
- New specimen geometries or materials
- Extended parameter ranges
- Different measurement conditions
- Validation measurements for existing configurations

**Data quality improvements**:
- Error corrections in existing data
- Enhanced metadata documentation
- Improved data validation procedures

### 2. Code Contributions

**Analysis tools**:
- Data loading and preprocessing utilities
- Visualization tools for wavefield data
- Domain shift quantification methods
- Benchmark evaluation scripts

**Machine learning baselines**:
- Domain adaptation algorithms
- Robustness evaluation methods
- Transfer learning implementations
- Uncertainty quantification approaches

### 3. Documentation Contributions

**Technical documentation**:
- Improved experimental protocols
- Enhanced methodology descriptions
- Usage examples and tutorials
- Best practices guides

**Scientific contributions**:
- Literature reviews
- Comparative studies
- Novel analysis methods
- Validation studies

## Contribution Guidelines

### Data Contributions

**Quality standards**:
- Follow established measurement protocols (see [METHODOLOGY.md](METHODOLOGY.md))
- Provide complete metadata documentation
- Ensure data integrity and validation
- Include uncertainty estimates where applicable

**Format requirements**:
- Use standard file formats (HDF5 recommended)
- Follow established naming conventions
- Include all necessary calibration information
- Provide clear documentation of any deviations from standard protocols

### Code Contributions

**Development standards**:
- Follow existing code style and conventions
- Include comprehensive documentation
- Provide unit tests for new functionality
- Ensure compatibility with existing tools

**Submission process**:
1. Fork the repository
2. Create a feature branch for your changes
3. Implement your contribution with appropriate tests
4. Submit a pull request with detailed description

### Documentation Contributions

**Writing standards**:
- Use clear, scientific language
- Include references to relevant literature
- Provide examples where appropriate
- Follow existing documentation structure

## Review Process

### Data Review

**Technical validation**:
- Verification of measurement protocols
- Quality assessment of data integrity
- Consistency checks with existing dataset
- Physical plausibility validation

**Scientific review**:
- Evaluation of scientific merit
- Assessment of contribution to domain shift research
- Review of methodology and experimental design
- Validation of results and conclusions

### Code Review

**Functionality review**:
- Correctness of implementation
- Performance and efficiency considerations
- Integration with existing codebase
- User interface and usability

**Quality review**:
- Code style and documentation
- Test coverage and reliability
- Error handling and robustness
- Maintainability and extensibility

## Community Guidelines

### Communication

**Be respectful and inclusive**:
- Welcome contributors from all backgrounds
- Provide constructive feedback
- Acknowledge contributions and credit appropriately
- Foster collaborative problem-solving

**Be clear and specific**:
- Provide detailed descriptions of issues and proposals
- Include relevant context and background information
- Ask questions when requirements are unclear
- Document decisions and rationale

### Collaboration

**Coordinate with others**:
- Check for existing work before starting new contributions
- Communicate plans and progress regularly
- Seek feedback early and often
- Be responsive to review comments and suggestions

## Recognition and Attribution

### Contributor Recognition

- All contributors will be acknowledged in project documentation
- Significant contributions may warrant co-authorship on publications
- Contributors retain credit for their specific contributions
- Regular contributors may be invited to join the core development team

### Citation Guidelines

When using WaveDS in research:
- Cite the primary dataset publication (when available)
- Acknowledge specific contributors for data or tools used
- Follow established academic attribution practices
- Consider involving dataset creators in collaborative research

## Legal and Ethical Considerations

### Data Licensing

- All contributions must be compatible with CC0 1.0 Universal License
- Contributors must have rights to contribute their data or code
- Clear documentation of data provenance and permissions required
- Compliance with institutional and legal requirements

### Ethical Research Practices

- Follow established research ethics guidelines
- Ensure reproducibility and transparency
- Report limitations and potential biases honestly
- Consider broader impacts of research applications

## Future Development

### Roadmap

The project development priorities include:
1. Expanding dataset coverage and diversity
2. Developing comprehensive analysis tools
3. Establishing benchmark evaluation protocols
4. Building community of practice around domain shift research

### Long-term Vision

WaveDS aims to become a foundational resource for domain shift research in physics-based measurement systems, enabling advances in robust machine learning for real-world applications.
